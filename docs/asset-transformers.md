# Asset Transformers

Asset Transformers take an Asset and an Image Transform definition and return an `AssetTransformResult`. Every result has a URL
and MIME type. The URL can point to output generated by Craft or an external service.

These docs use three terms:

- A **transform** is one operation, or its definition: inline parameters or a named Image Transform.
- A **transformer** is what a disk (or one call) uses to run transforms: a driver plus that driver's inline settings,
  written as `['driver' => 'craft', ...settings]`, the same way a disk is written as `['driver' => 's3', ...settings]`.
- A **driver** is the PHP class behind a transformer, registered under a **driver name** such as `craft` or `imgix`. You
  only need drivers when you write or register one (see [Implementing a custom driver](#implementing-a-custom-driver)).

Where a transformer is expected, a string names a driver, the same way a disk's `'driver' => 's3'` does. `'imgix'` means
`['driver' => 'imgix']`: the `imgix` driver with no inline settings, so it uses its own config.

`CraftCms\Cms\Asset\AssetTransformers` handles all three. It registers drivers with `extend()`, resolves a disk's transformer
with `forDisk()`, and runs transforms with `transform()`.

## Choosing a transformer per disk

Each disk in Laravel's `config/filesystems.php` can set an `asset_transformer` key, which picks the transformer for Assets
stored on it:

```php
// config/filesystems.php
'disks' => [
    // No key: the `craft` transformer, with its defaults.
    'local' => ['driver' => 'local', 'root' => storage_path('app/public')],

    // Shorthand for ['driver' => 'imgix']: the imgix driver, using its own config.
    's3' => ['driver' => 's3', /* ... */, 'asset_transformer' => 'imgix'],

    // A driver plus inline settings.
    'uploads' => ['driver' => 's3', /* ... */, 'asset_transformer' => [
        'driver' => 'craft',
        'output_disk' => 'transforms',
        'subpath' => '_transforms',
    ]],

    // A scoped disk without the key follows the disk it wraps, so this uses `imgix`.
    'blog' => ['driver' => 'scoped', 'disk' => 's3', 'prefix' => 'blog'],
],
```

A disk and its transformer are configured together, so switching a volume's disk per environment also switches its
transformer. Laravel ignores keys it doesn't use.

Volumes on the same disk share its transformer. To give one of them a different transformer, point that volume at its own
disk with its own `asset_transformer` key, such as a `scoped` disk wrapping the shared one.

Craft chooses one transformer for each request, in this order:

1. The `transformer` argument passed to `transform()`, a driver name.
2. The `asset_transformer` key on the Asset's disk. A `scoped` disk without the key follows its `disk`, which can be a disk
   name or an inline array.
3. The `craft` transformer, with its defaults.

When the `transformer` argument names the disk's own driver, the disk's inline settings still apply. Any other driver name
gets no inline settings. To use different inline settings, such as another `output_disk`, define another disk.

```php
$result = $asset->transform([
    'width' => 1200,
    'format' => 'webp',
], transformer: 'imgix');

$url = $result->url;
```

Twig uses the same named argument:

```twig
<img src="{{ asset.transform({
    width: 1200,
    format: 'webp',
}, transformer: 'imgix').url }}" alt="">
```

GraphQL accepts a driver name:

```graphql
query {
  asset(id: 42) {
    url(transformer: "imgix", width: 1200, format: "webp")
  }
}
```

Craft uses `transformer` to choose the transformer instead of passing it as a transform parameter.

### Invalid configuration

Craft checks a transformer when it resolves one, not at boot, so drivers that packages register late still count. If an
`asset_transformer` value or `transformer` argument names a driver that isn't registered, or an `asset_transformer` array
has no string `driver` key:

- With debug mode on, Craft throws an `AssetTransformDriverNotFoundException` or `InvalidAssetTransformException` naming the
  disk.
- Otherwise, Craft logs a warning naming the disk, once per request, and uses the `craft` transformer with its defaults.

Craft can't detect a misspelled key name, such as `asset_transfomer`, because disks carry keys for other packages too. A disk
with a misspelled key uses the `craft` transformer.

## Transform definitions

`Asset::transform()` accepts these definition forms:

- An inline parameter array
- A named Image Transform handle
- An `ImageTransform` data object
- An array with a `transform` key naming a base transform, plus parameter overrides

```php
$result = $asset->transform([
    'transform' => 'card',
    'width' => 800,
], transformer: 'remote-images');
```

Craft resolves the base transform, applies overrides, selects the transformer, and validates the parameters before calling
the driver. Core parameters use these rules by default:

| Parameter | Default accepted value |
| --- | --- |
| `fill` | String |
| `format` | An `ImageTransformFormat` value |
| `height` | Integer greater than zero |
| `interlace` | An `ImageTransformInterlace` value |
| `mode` | An `ImageTransformMode` value |
| `position` | An `ImageTransformPosition` value |
| `quality` | Integer from 1 through 100 |
| `upscale` | Boolean |
| `width` | Integer greater than zero |

A driver can add parameters or replace a core parameter's validation rules. Craft validates core and declared parameters,
passes undeclared parameters through unchanged, and sorts every parameter by name before calling the driver. A Cloudflare
driver, for example, can replace the `quality` rule to accept integers and presets such as `high`.

Named Image Transforms key custom parameter values by driver name, since drivers declare the parameters. Disks that use the
same driver share them.

## The Craft transformer

The `craft` driver generates transforms with Craft's local image processing. It reads these inline settings from a disk's
`asset_transformer` array:

| Setting | Default | Meaning |
| --- | --- | --- |
| `output_disk` | The source disk | The disk where Craft stores generated transforms. |
| `subpath` | None | A path on the output disk to store generated transforms below. Only used with `output_disk`. |
| `has_urls` | `false` | Whether the output disk serves public URLs. Only used with `output_disk`; otherwise the volume's own setting applies. |
| `generate_transforms_before_page_load` | `false` | Whether Craft generates each transform before returning its URL, rather than when the URL is first requested. |

```php
'uploads' => [
    'driver' => 's3',
    // ...
    'asset_transformer' => [
        'driver' => 'craft',
        'output_disk' => 'transforms',
        'subpath' => '_transforms',
        'has_urls' => true,
    ],
],
```

Use `env()` for values that differ between environments.

The driver rejects unsupported source formats, maintains the transform index, supports deferred generation, and preloads index
data for Asset queries. Each index row records where its file is stored, so changing `output_disk` or `subpath` makes Craft
generate new transforms at the new location. Craft doesn't delete files from the old location, so clear it yourself.
Toggling `has_urls` or `generate_transforms_before_page_load` reuses existing transforms.

Code that requires generated files immediately can use `CraftAssetTransformDriver::withImmediateTransforms()` to override
`generate_transforms_before_page_load` for a callback. The driver restores the configured behavior after the callback returns
or throws.

## Implementing a custom driver

Implement `AssetTransformDriver` to add a driver:

```php
<?php

declare(strict_types=1);

namespace Acme\RemoteImages;

use CraftCms\Cms\Asset\Contracts\AssetTransformDriver;
use CraftCms\Cms\Asset\Data\AssetTransformDriverDefinition;
use CraftCms\Cms\Asset\Data\AssetTransformRequest;
use CraftCms\Cms\Asset\Data\AssetTransformResult;
use CraftCms\Cms\Asset\Exceptions\AssetTransformFailedException;
use CraftCms\Cms\Ui\Controls\Number;
use CraftCms\Cms\Ui\Nodes\Field;
use CraftCms\Cms\Support\File;

use function CraftCms\Cms\t;

class RemoteImageDriver implements AssetTransformDriver
{
    public function definition(): AssetTransformDriverDefinition
    {
        return new AssetTransformDriverDefinition(
            label: t('Remote Images', category: 'remote-images'),
            parameterRules: [
                'devicePixelRatio' => ['numeric', 'between:1,4'],
            ],
            parameterFields: [
                'devicePixelRatio' => Field::make(
                    t('Device Pixel Ratio', category: 'remote-images'),
                    Number::make('devicePixelRatio')->min(1)->max(4),
                ),
            ],
        );
    }

    public function transform(AssetTransformRequest $request): AssetTransformResult
    {
        // Inline settings from the disk's `asset_transformer` array win over the driver's own config.
        $endpoint = $request->transformer->settings['endpoint'] ?? config('services.remote_images.endpoint');
        $sourceUrl = $request->asset->getUrl();

        if (! is_string($endpoint) || $endpoint === '' || $sourceUrl === null) {
            throw new AssetTransformFailedException('The remote image request could not be created.');
        }

        $format = $request->parameters['format'] ?? $request->asset->getExtension();
        $query = http_build_query([
            'source' => $sourceUrl,
            ...$request->parameters,
        ]);
        $url = sprintf('%s/render?%s', rtrim($endpoint, '/'), $query);

        return new AssetTransformResult(
            url: $url,
            mimeType: File::getMimeTypeByExtension("transform.{$format}") ?? 'application/octet-stream',
        );
    }
}
```

This example requires a public source Asset URL. For private Assets, upload the source or sign the request using the
service's supported flow.

### The driver definition

`AssetTransformDriverDefinition` defines the driver's label and parameters:

- `label` is the name that the Control Panel displays.
- `parameterRules` maps parameter names to Laravel validation rules.
- `parameterFields` maps parameter names to the `Field` nodes shown in named Image Transform forms.

Core rules are defaults. When a driver declares a core parameter name, its rules replace the defaults for that driver.
Craft stores values from a driver's named Image Transform fields under its driver name. Those values override the core
value when a request uses that driver. The driver must validate any undeclared parameters it uses or forwards.

### Driver settings and credentials

A driver reads its credentials and defaults from its own config, such as an `imgix` entry in `config/services.php`. Inline
settings from a disk's `asset_transformer` array arrive in `$request->transformer->settings`, and should win over the
driver's own config, the way Laravel's SES and Postmark mail transports merge mailer settings over `services.php`. Validate
inline settings before using them, since Craft passes them through unchanged.

Each parameter field must meet both requirements:

- The array key and Control path match a declared custom parameter.
- The Control submits a value that satisfies the parameter's validation rules.

Parameter fields are optional. Omit the field when a parameter is only for inline PHP or Twig. Craft does not add custom
parameters to the GraphQL transform argument schema.

### The transform request

Each `AssetTransformRequest` contains:

- `asset`: the source `Asset` element;
- `transformer`: the selected transformer, with its `driver` name and inline `settings`;
- `parameters`: normalized and validated core and custom parameters.

Use `$request->transformer` for the selected transformer. The `transformer` argument never appears in
`$request->parameters`. Read the source disk from `$request->asset`.

### The transform result

`AssetTransformResult` requires a URL and MIME type. It can also report the output's filename, dimensions, and byte size:

```php
return new AssetTransformResult(
    url: $result->url,
    mimeType: $result->mimeType,
    filename: $result->filename,
    width: $result->width,
    height: $result->height,
    size: $result->size,
);
```

Return metadata for the output, not the source Asset. GraphQL reads these values when resolving transformed Asset fields.

### Registering the driver

Register the driver from a plugin or application service provider:

```php
<?php

declare(strict_types=1);

namespace Acme\RemoteImages;

use CraftCms\Cms\Asset\AssetTransformers;
use Illuminate\Contracts\Container\Container;
use Illuminate\Support\ServiceProvider;

class RemoteImagesServiceProvider extends ServiceProvider
{
    public function boot(AssetTransformers $transformers): void
    {
        $transformers->extend(
            'remote-images',
            fn (Container $container) => $container->make(RemoteImageDriver::class),
        );
    }
}
```

The driver name identifies the driver. After registration, set `'asset_transformer' => 'remote-images'` on a disk, or pass
`transformer: 'remote-images'` to `transform()`.

Laravel's driver manager resolves and caches one driver instance per driver name. Keep request state in the
`AssetTransformRequest`, not on that shared instance.

## Optional transform preloading

Implement `PreloadsAssetTransforms` when the backing service can prepare a batch more efficiently than individual requests:

```php
use CraftCms\Cms\Asset\Contracts\PreloadsAssetTransforms;

class RemoteImageDriver implements AssetTransformDriver, PreloadsAssetTransforms
{
    // definition() and transform() ...

    public function preloadAssetTransforms(array $requests): void
    {
        $this->client->preload($requests);
    }
}
```

Asset queries using `withTransforms()` group requests by driver and call this method once for each group. A group can contain
requests for several disks, so read inline settings from each request's `transformer` property. Preloading is only a
hint; the driver does not have to materialize the output.

## Cache invalidation

Drivers with their own transform index or remote cache can listen for `AssetTransformsInvalidating`, which tells the driver to
invalidate every result for an Asset.

Transformer settings live in config files, so Craft doesn't fire an event when they change. A driver whose results depend on
its settings should include them in its cache keys, the way the `craft` driver keys its index by output location.

## Failure behavior

When a driver cannot fulfill a request:

- Throw `NotSupportedException` when the driver does not support the source Asset type.
- Throw `AssetTransformFailedException` when a supported transform fails.
- Let unexpected exceptions propagate.

Craft uses `NotSupportedException` to fall back to file-kind icons in Control Panel thumbnail and preview contexts. Craft
reports other transform failures to the caller.
