# Asset Transformers

Asset Transformers take an Asset and an Image Transform definition and return an `AssetTransformResult`. Every result has a URL
and MIME type. The URL can point to output generated by Craft or an external service.

An Asset Transformer and its driver have separate jobs:

- An **Asset Transformer** is a project-configured profile with a name, handle, driver, and driver settings.
- An **Asset Transform driver** is the PHP class that validates parameters and produces results.

Several transformers can use the same driver with different settings. For example, two profiles can use one remote image
driver while targeting different accounts or delivery domains.

Craft stores transformers in Project Config under `assetTransformers`. Manage them under **Settings → Assets → Asset
Transformers**. Each driver defines its own settings fields with the Control Panel Form system.

Craft will not delete a transformer while it is the default or is assigned to a volume. Renaming its handle updates the
default and volume references. If a plugin-provided driver is unavailable, Craft keeps the transformer and its settings in
Project Config, marks the driver as unavailable, and refuses to save the transformer until the driver returns.

## Transformer selection

Craft chooses one transformer for each request, in this order:

1. The `transformer` argument passed to `transform()`.
2. The transformer assigned to the Asset's volume.
3. The [`defaultAssetTransformer`](../src/Config/GeneralConfig.php) general config setting, whose default is `craft`.

Pass an explicit transformer with an inline definition:

```php
$result = $asset->transform([
    'width' => 1200,
    'format' => 'webp',
], transformer: 'remote-images');

$url = $result->url;
```

Twig uses the same named argument:

```twig
<img src="{{ asset.transform({
    width: 1200,
    format: 'webp',
}, transformer: 'remote-images').url }}" alt="">
```

GraphQL accepts the same argument:

```graphql
query {
  asset(id: 42) {
    url(transformer: "remote-images", width: 1200, format: "webp")
  }
}
```

Craft uses `transformer` to choose the profile instead of passing it as a transform parameter.

## Transform definitions

`Asset::transform()` accepts these definition forms:

- An inline parameter array
- A named Image Transform handle
- An `ImageTransform` data object
- An array with a `transform` key naming a base transform, plus parameter overrides

```php
$result = $asset->transform([
    'transform' => 'card',
    'width' => 800,
], transformer: 'remote-images');
```

Craft resolves the base transform, applies overrides, selects the transformer, and validates the parameters before calling
the driver. Core parameters use these rules by default:

| Parameter | Default accepted value |
| --- | --- |
| `fill` | String |
| `format` | An `ImageTransformFormat` value |
| `height` | Integer greater than zero |
| `interlace` | An `ImageTransformInterlace` value |
| `mode` | An `ImageTransformMode` value |
| `position` | An `ImageTransformPosition` value |
| `quality` | Integer from 1 through 100 |
| `upscale` | Boolean |
| `width` | Integer greater than zero |

A driver can add parameters or replace a core parameter's validation rules. Craft validates core and declared parameters,
passes undeclared parameters through unchanged, and sorts every parameter by handle before calling the driver. A Cloudflare
driver, for example, can replace the `quality` rule to accept integers and presets such as `high`.

Named Image Transforms key custom parameter values by transformer UUID. The UUID keeps values separate for profiles with
different parameter sets, even when they share a driver.

## The Craft transformer

Craft reserves the `craft` transformer and driver. Its name, handle, and driver cannot change, and the transformer cannot be
deleted. You can still edit these settings:

- **Output Filesystem** selects where Craft stores generated transforms. Leave it empty to use the source Asset's
  filesystem.
- **Output Subpath** places generated transforms below a subpath on the selected output filesystem.
- **Generate Transforms Before Page Load** controls whether Craft generates each transform before returning its URL.
  Otherwise, Craft generates it when the URL is first requested.

The filesystem settings accept environment-variable aliases. The built-in driver resolves the aliases before choosing its
output filesystem.

The Craft driver uses Craft's local image transformer. It rejects unsupported source formats, maintains the transform index,
supports deferred generation, and preloads index data for Asset queries.

Code that requires generated files immediately can use `CraftAssetTransformDriver::withImmediateTransforms()` to override
the profile setting for a callback. The driver restores the configured behavior after the callback returns or throws.

## Implementing a custom driver

Implement `AssetTransformDriver` to add a driver:

```php
<?php

declare(strict_types=1);

namespace Acme\RemoteImages;

use CraftCms\Cms\Asset\Contracts\AssetTransformDriver;
use CraftCms\Cms\Asset\Data\AssetTransformDriverDefinition;
use CraftCms\Cms\Asset\Data\AssetTransformRequest;
use CraftCms\Cms\Asset\Data\AssetTransformResult;
use CraftCms\Cms\Asset\Exceptions\AssetTransformFailedException;
use CraftCms\Cms\Form\Controls\Number;
use CraftCms\Cms\Form\Controls\Text;
use CraftCms\Cms\Form\Nodes\Field;
use CraftCms\Cms\Support\Env;
use CraftCms\Cms\Support\File;

use function CraftCms\Cms\t;

class RemoteImageDriver implements AssetTransformDriver
{
    public function definition(): AssetTransformDriverDefinition
    {
        return new AssetTransformDriverDefinition(
            name: t('Remote Images', category: 'remote-images'),
            parameterRules: [
                'devicePixelRatio' => ['numeric', 'between:1,4'],
            ],
            parameterFields: [
                'devicePixelRatio' => Field::make(
                    t('Device Pixel Ratio', category: 'remote-images'),
                    Number::make('devicePixelRatio')->min(1)->max(4),
                ),
            ],
            settingsFields: [
                Field::make(
                    t('Endpoint', category: 'remote-images'),
                    Text::make('endpoint'),
                )->required(),
            ],
        );
    }

    public function transform(AssetTransformRequest $request): AssetTransformResult
    {
        $endpoint = Env::parse($request->transformer->settings['endpoint'] ?? null);
        $sourceUrl = $request->asset->getUrl();

        if (! is_string($endpoint) || $endpoint === '' || $sourceUrl === null) {
            throw new AssetTransformFailedException('The remote image request could not be created.');
        }

        $format = $request->parameters['format'] ?? $request->asset->getExtension();
        $query = http_build_query([
            'source' => $sourceUrl,
            ...$request->parameters,
        ]);
        $url = sprintf('%s/render?%s', rtrim($endpoint, '/'), $query);

        return new AssetTransformResult(
            url: $url,
            mimeType: File::getMimeTypeByExtension("transform.{$format}") ?? 'application/octet-stream',
        );
    }
}
```

This example requires a public source Asset URL. For private Assets, upload the source or sign the request using the
service's supported flow.

### The driver definition

`AssetTransformDriverDefinition` defines the driver's Control Panel fields and validation rules:

- `name` is the driver name that the Control Panel displays.
- `parameterRules` maps parameter handles to Laravel validation rules.
- `parameterFields` maps parameter handles to the `Field` nodes shown in named Image Transform forms.
- `settingsFields` contains the `Field` nodes used to configure a transformer profile.

Core rules are defaults. When a driver declares a core parameter handle, its rules replace the defaults for that driver.
Craft stores values from a driver's named Image Transform fields against the transformer UUID. Those values override the
core value when Craft selects that transformer. The driver must validate any undeclared parameters it uses or forwards.

Each settings field must use a single-segment Control path. The Control Panel only persists submitted settings declared
by the driver. Validate the resolved values again before using them, especially URLs, credentials, and environment-variable
aliases.

Craft stores transformer settings in Project Config. Store credentials as environment-variable aliases rather than literal
secrets, and resolve them inside the driver with `Env::parse()`.

Each parameter field must meet both requirements:

- The array key and Control path match a declared custom parameter.
- The Control submits a value that satisfies the parameter's validation rules.

Parameter fields are optional. Omit the field when a parameter is only for inline PHP or Twig. Craft does not add custom
parameters to the GraphQL transform argument schema.

### The transform request

Each `AssetTransformRequest` contains:

- `asset`: the source `Asset` element;
- `transformer`: the selected transformer profile, including its driver settings;
- `parameters`: normalized and validated core and custom parameters.

Use `$request->transformer` for the selected profile. The transformer handle never appears in
`$request->parameters`.

### The transform result

`AssetTransformResult` requires a URL and MIME type. It can also report the output's filename, dimensions, and byte size:

```php
return new AssetTransformResult(
    url: $result->url,
    mimeType: $result->mimeType,
    filename: $result->filename,
    width: $result->width,
    height: $result->height,
    size: $result->size,
);
```

Return metadata for the output, not the source Asset. GraphQL reads these values when resolving transformed Asset fields.

### Registering the driver

Register the driver from a plugin or application service provider before Craft resolves Asset Transformer settings:

```php
<?php

declare(strict_types=1);

namespace Acme\RemoteImages;

use CraftCms\Cms\Asset\AssetTransformDrivers;
use Illuminate\Contracts\Container\Container;
use Illuminate\Support\ServiceProvider;

class RemoteImagesServiceProvider extends ServiceProvider
{
    public function boot(AssetTransformDrivers $drivers): void
    {
        $drivers->extend(
            'remote-images',
            fn (Container $container) => $container->make(RemoteImageDriver::class),
        );
    }
}
```

The registration handle identifies the driver implementation. After registration, create an Asset Transformer in the
Control Panel and select **Remote Images** as its driver. Volumes, the `transformer` argument, and
`defaultAssetTransformer` reference the configured transformer handle.

Laravel's driver manager resolves and caches one driver instance per registration handle. Keep request state in the
`AssetTransformRequest`, not on that shared instance.

## Optional transform preloading

Implement `PreloadsAssetTransforms` when the backing service can prepare a batch more efficiently than individual requests:

```php
use CraftCms\Cms\Asset\Contracts\PreloadsAssetTransforms;

class RemoteImageDriver implements AssetTransformDriver, PreloadsAssetTransforms
{
    // definition() and transform() ...

    public function preloadAssetTransforms(array $requests): void
    {
        $this->client->preload($requests);
    }
}
```

Asset queries using `withTransforms()` group requests by driver and call this method once for each group. A group can contain
several transformer profiles, so read profile settings from each request's `transformer` property. Preloading is only a
hint; the driver does not have to materialize the output.

## Cache invalidation and transformer changes

Drivers with their own transform index or remote cache can listen for these events:

- `AssetTransformsInvalidating` tells the driver to invalidate every result for an Asset.
- `AssetTransformerUpdating` fires when a transformer's driver or settings change.
- `AssetTransformerDeleting` fires before Craft removes a transformer profile.

The update event contains the old and new profiles. Key caches by transformer UUID because handles can change.

## Failure behavior

When a driver cannot fulfill a request:

- Throw `NotSupportedException` when the driver does not support the source Asset type.
- Throw `AssetTransformFailedException` when a supported transform fails.
- Let unexpected exceptions propagate.

Craft uses `NotSupportedException` to fall back to file-kind icons in Control Panel thumbnail and preview contexts. Craft
reports other transform failures to the caller.
