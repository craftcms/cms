@craftcms/garnish playground

Interactive demos wired against the real source (../src/index.ts + ../src/compat.ts) with Vite HMR. Open the event-log panel (bottom-right) to watch events fire.

1. Modal

Construct new Modal() instances and drive their lifecycle. Every show / hide / fadeIn / fadeOut / escape event is piped into the log panel.

2. Focusable matcher & focus trap

The container below mixes focusable and non-focusable elements. Run the matcher to highlight what getFocusableElements / isKeyboardFocusable select, then open the focus-trap modal and press Tab / Shift+Tab to see cycling stay trapped.

3. Compat upgrade path

Calls installGarnishCompat(), then defines a subclass with the legacy Garnish.Modal.extend({ init, onShow }) API and a this.base() super-call — proving the legacy authoring contract works in the browser against the modern class Modal.

4. Draggable & resizable Modal

Modal's draggable / resizable options are now fully supported (they used to throw). Open each modal and drag/resize it live — dragStart / drag / dragStop events are piped into the log panel.

Free-floating boxes inside the bounded area below. The green boxes use new DragMove(box) directly; the blue box uses a raw new BaseDrag(box, {onDrag}) that sets left/top itself. Every dragStart / drag / dragStop fires into the log (drag events are throttled in the log to one line per gesture). The third green box is X-axis-locked ({axis: 'x'}).

7. Drag with helpers (clones + return-to-source)

These rows use new Drag(items, {...}). Grabbing an item builds floating helper clones that trail the cursor with lag (createHelper + the lag-follow RAF loop). On drop the helpers animate back to their source via the Web Animations API (returnHelpersToDraggees) — or fade out (fadeOutHelpers) if you chose that mode. Every dragStart / drag / dragStop (and returnHelpersToDraggees) fires into the log.

8. DragDrop — drop targets & hit detection

A new DragDrop({ dropTargets, ... }) wired to the draggable chips on the left and the three drop zones on the right. While you drag a chip, the zone under the cursor highlights (the activeDropTargetClass is toggled) and dropTargetChange logs the new active target (or null). On release, the demo reads $activeDropTarget in its own dragStop handler to report which zone — if any — the drop landed on. Overlap resolves to the first target in document order (first-match wins).

9. DragSort — reorderable list

A new DragSort(items, { insertion, ... }) wired to the sortable list below. Grab a row and drag it up or down — the dragged row's helper trails the cursor while the list reflows live around a dashed insertion placeholder showing where it will land (insertionPointChange logs each move). On drop the new order is committed; if anything moved, sortChange logs the new index order. The second list is axis: 'y'-locked. Handles carry touch-action: none.
