# Factory

`create()` builds an element in JavaScript and hands it back, with no markup and no jQuery.

```js
import {create} from '@craftcms/ui';

const save = create(
  'craft-button',
  {variant: 'primary', type: 'submit'},
  'Save'
);

container.append(save);
```

It takes the tag, an object of properties, and any children (nodes or strings). Nothing is inserted for you — append the result where it belongs.

## Typed by tag

The properties are checked against the element's class in `HTMLElementTagNameMap`, so every component gets typed properties without a factory of its own. A misspelled or unknown property is a compile error:

```ts
create('craft-button', {varient: 'primary'}); // error: 'varient' does not exist
```

Properties that are `undefined` are skipped, so optional config can pass straight through.

## Attributes

Set attributes with no matching property, such as `data-*` and `aria-*`, through `attrs`. `true` sets an empty attribute; `false`, `null` and `undefined` leave it off.

```js
const url = create('input', {
  type: 'url',
  name: 'url',
  attrs: {'aria-label': 'URL'},
});
```

## Form values

Controls that carry a value post it under their `name`:

```js
const picker = create('craft-slide-picker', {
  name: 'columns',
  min: 1,
  max: 6,
  value: '3',
});
form.append(picker);
```

## Copy prompts

`showCopyTextPrompt()` is the one builder that inserts itself. It opens a dialog showing a value with a copy button, appends it to `<body>`, and removes it once it closes.

```js
import {showCopyTextPrompt} from '@craftcms/ui';

showCopyTextPrompt({label: 'Full URL', value: url});
```

## Legacy `Craft.ui` builders

The legacy `Craft.ui.create*()` functions translate their old config keys onto `create()`. They live with the rest of the legacy shims, not in `@craftcms/ui`.

Reach for [Utilities](?path=/docs/javascript-api-utilities--docs) for the smaller pieces.
