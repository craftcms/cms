# Button Group

`<craft-button-group>` joins related buttons into a single visual unit.

## Radio Mode

Given a `name`, the group becomes a single-choice control — a segmented toggle rather than a row of independent buttons:

In this mode the group is form-associated and posts like any other field, so a segmented control does not need a hidden input beside it.

## Choosing Between Modes

Without a `name` the buttons are actions; with one they are options.

That is a real semantic difference, not styling: in radio mode the group is announced as a radio group and arrow keys move between the options, which is wrong for a row of independent actions and right for a choice.

## Icon Buttons

A segmented control of icons is compact and easy to misread. Each button still needs a name — see [Icon](?path=/docs/components-icon--docs) — because the group announces the choice, not what each option means.

## Accessibility

- Given a `name`, name the group too, with `aria-label` or `aria-labelledby` on `craft-button-group`. Its buttons are announced as pressed or not, and the group name says what they choose between.
- Keep a group with a `name` to its options. Every `craft-button` inside it, including a menu's invoker, is treated as one of them.
- Each button is its own Tab stop. Arrow keys don't move between them.
- For a single choice that should be announced and operated as radio buttons, use `craft-radio-group`.
