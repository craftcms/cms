# Badge

`<craft-badge>` is a small status pill: a colored [Indicator](?path=/docs/components-indicator--docs) dot followed by a label.
Use it to surface an object's state where it is read at a glance — an entry's status in an index, an order's payment state in a header.

<Canvas of={BadgeStories.Default} sourceState="shown" />

The label is the default slot, and `fill` sets the color.
The badge renders its surface, border, and text in the quiet tone of that color, and the indicator in the loud one, so the pill stays legible against the page while the dot carries the signal.

## Color

`fill` takes a value from the shared `Color` palette:

<Canvas of={BadgeStories.AllColors} sourceState="shown" />

Unlike Indicator, the badge is limited to the palette and does not take arbitrary CSS colors — `fill` is typed as `ColorValue`, so an unknown color fails to type-check rather than rendering as nothing.

Setting it reflects the resolved color onto the host's `data-color` attribute, which is what scopes the `--c-color-*` tokens the badge's styles read.
That is the same mechanism described on the [Colorable](?path=/docs/tokens-colorable--docs) page.

### Semantic colors

`Color` also carries aliases that resolve to palette values — `Color.Success` is `emerald`, `Color.Warning` is `orange`, `Color.Danger` is `red`, `Color.Info` is `blue`.
Reach for these when the color carries meaning, so intent survives a palette retune:

## Styling

The badge sizes itself in `em`, so set `font-size` on the host to scale the whole pill, indicator included:

```css
craft-badge {
  font-size: var(--c-text-sm);
}
```

Its colors come from the generic colorable tokens — `--c-color-fill-quiet` for the surface, `--c-color-border-quiet` for the border, `--c-color-on-quiet` for the text.
Because `fill` scopes those tokens, change a badge's color through `fill` rather than by overriding them.

## Accessibility

The default indicator is decorative and deliberately unlabeled: the badge's own text already names the status, and a labeled dot beside it would be announced twice.

Replace the `prefix` with something meaningful and that changes — give it its own accessible name, such as a `label` on the [Indicator](?path=/docs/components-indicator--docs) or [Icon](?path=/docs/components-icon--docs).

Always give a badge visible text. Without it, a badge is only a colored dot, and sighted users can tell its status only by color, which fails WCAG 1.4.1 Use of Color.
An accessible name doesn't fix this, whether it's an `aria-label` or a labeled Indicator in `prefix`: it reaches screen-reader users, but not people who can't tell the colors apart.
A tooltip doesn't fix it either, because it only appears on hover or focus.

If space is tight, keep a short visible word, such as "Live" or "Off", rather than dropping the text.
