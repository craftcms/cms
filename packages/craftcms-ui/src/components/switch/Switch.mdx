# Switch

`<craft-switch>` toggles a setting that takes effect immediately.

<Canvas of={SwitchStories.Default} sourceState="shown" />

It is the modern replacement for the legacy lightswitch, and posts through a hidden input so it behaves like any other form field.

## Switch or Checkbox?

The two look different because they mean different things:

- **Switch** — the change happens now. Turning it on _is_ the action.
- **[Checkbox](?path=/docs/form-controls-choice-controls-checkbox--docs)** — the value is part of a form, and nothing happens until it is submitted.

A switch that only takes effect after a Save button is a switch that lied about what it does.

## State Labels

`on-label` and `off-label` render text either side of the control describing the two states, matching the legacy lightswitch. Clicking either label sets that state.

They are announced as a single description rather than as two loose strings — the visible labels are hidden from assistive technology and replaced with one linked description, so a screen reader hears what the switch does rather than the words "on" and "off" floating beside it.

## The Mixed State

`indeterminate` renders the third state, again matching the legacy lightswitch, and posts `indeterminate-value` rather than the on value.

It is only meaningful while the switch is off, and is cleared as soon as the switch is turned on — a switch cannot be both on and undecided.

## Values

`value` is what the hidden input posts when the switch is on, defaulting to `1`. It is named `checkedValue` on the element itself, because Lion already defines a `value` accessor that proxies the input node.

## In PHP

In a Craft control panel screen, or a plugin's `settingsUi()`, describe the UI with `CraftCms\Cms\Ui\Ui` instead of writing markup.
`CraftCms\Cms\Ui\Controls\Lightswitch` renders a switch:

```php
use CraftCms\Cms\Ui\Controls\Lightswitch;
use CraftCms\Cms\Ui\Nodes\Field;
use CraftCms\Cms\Ui\Ui;

Ui::make([
    Field::make('Show the Post Date field', Lightswitch::make('showPostDate')
        ->onLabel('Show')
        ->offLabel('Hide')),
]);
```

`onLabel()` and `offLabel()` set the state labels.
`checkedValue()` sets the value that's submitted when it's on, and `indeterminate()` allows the mixed state.

## Accessibility

The control is exposed as a switch that's on or off.

Label it with the thing being switched, not with the states. "Enable comments" tells a person what the control governs; "On/Off" tells them only what a switch already looks like. If the label comes from elsewhere on the page through `aria-labelledby`, it must contain the text shown beside the switch, so voice control users can say what they see.

A few more things the component can't do for you:

- **Use it only for changes that apply straight away.** If the value waits for a Save button, use a checkbox. Toggling a switch shouldn't navigate, submit a form or move focus.
- **Give small switches room.** `size="small"` is 16px tall. Keep other controls clear of a 24px circle centered on it, or give it a visible label, which can be clicked to toggle it.
