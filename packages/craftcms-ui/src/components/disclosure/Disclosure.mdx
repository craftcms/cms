# Disclosure

`<craft-disclosure>` shows and hides a section of content.

<Canvas of={DisclosureStories.Collapsed} sourceState="shown" />

<Canvas of={DisclosureStories.Expanded} sourceState="shown" />

## Two Modes

**Slotted mode** is the usual one: a `slot="invoker"` trigger and `slot="content"` content, following Lion's collapsible convention. Without a slotted invoker it renders a default one from `label`:

<Canvas of={DisclosureStories.DefaultInvoker} sourceState="shown" />

The default invoker is a `plain`, `flush` button with a chevron after its label. The chevron points toward the end of the line while the disclosure is closed (right, or left in right-to-left text) and down while it's open. A slotted `craft-button` invoker with a chevron `icon` follows along, its chevron moved after its label.

In slotted mode, the content hangs off a hairline at the disclosure's start edge. Set `appearance="plain"` to drop the hairline and indent.

**External-target mode** wraps a bare `button` whose `aria-controls` names an element elsewhere in the document. Toggling flips that target's `data-state` between `expanded` and `collapsed`, and your CSS hides or shows it.

That second mode exists for server-rendered markup, where the trigger and the thing it reveals are rendered in different places and cannot be nested. It can also persist the state to a cookie via `cookie-name`, so a section stays as a person left it.

## Accordions

<Canvas of={DisclosureStories.Accordion} sourceState="shown" />

Several disclosures side by side make an accordion. Nothing enforces one-open-at-a-time — if you want that, close the others yourself.

Consider whether you want it at all. Collapsing a section a person just opened, because they opened another, is a common source of frustration.

## In PHP

In a Craft control panel screen, or a plugin's `settingsUi()`, describe the UI with `CraftCms\Cms\Ui\Ui` instead of writing markup.
A collapsible `CraftCms\Cms\Ui\Nodes\Group` renders as a disclosure, with the group's label on its button:

```php
use CraftCms\Cms\Ui\Controls\Handle;
use CraftCms\Cms\Ui\Controls\Number;
use CraftCms\Cms\Ui\Nodes\Field;
use CraftCms\Cms\Ui\Nodes\Group;
use CraftCms\Cms\Ui\Ui;

Ui::make([
    Group::make('advanced', [
        Field::make('Handle', Handle::make('handle')),
        Field::make('Max Length', Number::make('maxLength')->min(1)),
    ])
        ->label('Advanced')
        ->collapsible(),
]);
```

It starts collapsed. Call `expanded()` to start it open.

## Accessibility

The invoker carries `aria-expanded` and `aria-controls`, so the state and the relationship are both announced.

In external-target mode the component mirrors `aria-expanded` onto the button it wraps — which is why that mode expects a real `button`, not a div dressed as one.

Label the invoker with what it reveals rather than with the action, through `label` or the invoker's own content. "Advanced settings" says what is behind it; "Show more" says only that there is more.

If you slot your own invoker, make it a real `button` or `craft-button`. Anything else has no role for `aria-expanded` to attach to.

In external-target mode the rest is up to the page:

- Write the button's `aria-controls` yourself. The component logs an error when it names no element.
- Hide the collapsed target with `display: none` or the `hidden` attribute, keyed off `data-state="collapsed"`. Hiding it visually any other way leaves it in the accessibility tree and the Tab order.
- Render the target right after the button, so expanded content follows the trigger in the Tab order with nothing in between.
- If the target can't come right after the button, manage focus yourself. When it expands, move focus to the start of the target: its heading, or the target itself with `tabindex="-1"`. When it collapses while focus is inside it, move focus back to the button. Otherwise a keyboard or screen reader user is left at the trigger, with the content they just opened somewhere else on the page.
- Style the button with a visible focus indicator and a target of at least 24×24 CSS px.

For an accordion, each trigger belongs inside a heading. In external-target mode, wrap the whole `craft-disclosure` in the heading.
