# Select Color

`<craft-select-color>` offers the Craft palette as a dropdown, each option showing its swatch.

<Canvas of={SelectColorStories.Default} sourceState="shown" />

It is built on [Select Rich](?path=/docs/form-controls-select-controls-select-rich--docs), which is what lets each option carry a swatch beside its name.

## Palette, Not Arbitrary Color

Use this where the color has to come from the design system — a label color, a status color, anything that will sit alongside other Craft UI and needs to match it.

For an arbitrary color, use [Input Color](?path=/docs/form-controls-text-controls-input-color--docs), which takes any hex value. The two are not interchangeable: this one guarantees the result is a palette color, and that guarantee is the reason to choose it.

## The Transparent Option

An optional "transparent" entry sits alongside the colors, for a value meaning _no colour_ rather than a color that happens to be pale.

## Events

Picking a color is a commit, so the control emits `input` and `change` together:

```js
select.addEventListener('change', () => save(select.modelValue));
```

It also emits `model-value-changed`, Lion's internal protocol name. Prefer the native events — they carry the component as `event.target`.

## Accessibility

Each option is named by its color, so the list is usable without seeing the swatches.

Color names are not meanings, though. If a color carries significance in your interface — red for a problem, green for a healthy state — say so in the label or help text, because "Red" alone does not tell a person what choosing red will do.
