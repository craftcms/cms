# `craft-thumbnail` accessibility

## Requirements

- [x] An animated (GIF/WEBP) source is frozen to a static frame instead of autoplaying indefinitely, per WCAG 2.2.2 (Pause, Stop, Hide). Verified by `freezes an animated source instead of autoplaying, via the attribute or a .gif/.webp extension` in `thumbnail.browser.test.ts`, which asserts the cover canvas renders for an animated source.
- [x] Freezing doesn't depend solely on the server-rendered `animated` attribute — a `.gif`/`.webp` `src`/`srcset` is treated as animated too, so thumbnails rendered without that attribute (e.g. hand-authored markup) still freeze. Verified by `freezes an animated source instead of autoplaying, via the attribute or a .gif/.webp extension` in `thumbnail.browser.test.ts` (one thumbnail uses the attribute, another a `.gif`-suffixed `src` with no attribute) and by `freezes based on %s, without the animated attribute` in `thumbnail.test.ts`.
- [x] The underlying `<img>`'s accessible name (`alt`) stays exposed to assistive technology once frozen — the cover canvas sits visually on top of it but never replaces or hides it from the accessibility tree. Verified by `freezes an animated source instead of autoplaying, via the attribute or a .gif/.webp extension` in `thumbnail.browser.test.ts` via `computeAccessibleName()`.
- [x] The cover canvas itself is excluded from the accessibility tree (`aria-hidden="true"`), since it duplicates the underlying image purely for visual purposes. Verified by `freezes an animated source instead of autoplaying, via the attribute or a .gif/.webp extension` in `thumbnail.browser.test.ts` and by `freezes when the animated attribute is set, without altering the image` in `thumbnail.test.ts`.
- [x] The loading placeholder is a CSS background on the thumbnail box, so it adds nothing to the accessibility tree and leaves the image's accessible name alone. Verified by `thumbnail.test.ts`'s placeholder cases.
