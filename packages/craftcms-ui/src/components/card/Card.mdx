# Card

`<craft-card>` is a bordered, rounded surface that groups related content into a standalone block.
It holds an optional header, an optional thumbnail column, body content, and an optional footer.

<Canvas of={CardStories.Default} sourceState="shown" />

Use a card when the content is a block a person reads or acts on as a unit — an element in an index view, a settings group, a summary panel.
For a compact reference to a single entity in a list, use [Chip](?path=/docs/components-chip--docs) instead.

## Regions

A card has four regions, and each one is only rendered when there is something to put in it.
A card with body content alone is a plain bordered surface with no header or footer chrome.

The header appears as soon as the `label` attribute is set, or the `header`, `label`, or `actions` slot is filled:

The `actions` slot sits at the end of the header:

## Replacing the Header

## The Thumbnail

Content in the `thumbnail` slot renders in a fixed column beside the body:

`show-thumb` is on by default and gates the column entirely — set it to `false` to drop the thumbnail without removing the slotted content.
`thumb-alignment` puts the column at the `start` or the `end` of the body:

## Cover Cards

Set `cover-src` and the card becomes a cover card: the image fills it, and the header and body are laid over it.
Pass the image's `luminance` too — an asset's `analysis.colors.luminance` — and the card works out the rest.
Asset cards do this for images that can fill a card.

The text and controls are white or black, a little transparent.
Which one comes from the luminance, separately for the header (the top of the image) and the body (the bottom).
Whatever's laid behind them is as light as it can be while keeping them legible.
A cover card's `data-color` only colors its border, in the page's theme, as a normal card's would be. What's laid over the image keeps the white or black that the image calls for.

When the header has a label, from the `label` attribute or slot, or a `[data-card-label]` element in the `header` slot, it gets a bar of its own, the height of a normal card's header, blurred and filled with just enough black or white for the label:

<Canvas of={CardStories.Cover} sourceState="shown" />

Without a label, the header's controls sit on the image.
Where the image would let them fade into it, the checkbox and plain buttons get a backing, blurred like a label bar:

<Canvas of={CardStories.CoverBackedControls} />

Where the image is already dark or light enough, they're left bare:

<Canvas of={CardStories.CoverBareControls} />

The body's scrim fades in above the content, in black or white, whichever the bottom of the image needs, and the image blurs in under it, crisp at the top of the fade and fully blurred behind the text, so busy detail doesn't show through:

<Canvas of={CardStories.CoverScrim} />

Before an image is sampled, there's no luminance, so the card plays it safe with white over a heavier black:

<Canvas of={CardStories.CoverUnknownLuminance} />

A selected cover card gets an accent border and ring:

<Canvas of={CardStories.CoverActive} />

Small images, and narrow or wide ones, would be scaled up or cropped too far to fill a card, so Craft gives them a normal card with a thumbnail:

<Canvas of={CardStories.CoverAlongsideNormalCards} />

The card sets `data-theme` on what it lays over the image, so checkboxes and other controls take the matching theme, and `data-cover` (`bar`, `backed`, `bare`, or `body`), which `cp.css` styles them by.
The card's own border, corners, and shadow still follow the page's theme.
Header buttons are never flush in a cover card, so they line up with other cards' buttons.

## Colors

`data-color` tints the card with a palette color.
On a colored card, links take the card's text color and are underlined until hovered, so they don't clash with the fill.
White, gray, and slate cards keep the default link styling.

## Active State

`active` marks a card as selected, and is reflected to the host so it can be styled from outside the component.
Element index views bind it to row selection:

<Canvas of={CardStories.Active} sourceState="shown" />

`active` is presentational.
It does not make the card focusable or announce a selection, so a selectable list is responsible for its own control and its own semantics.

## Styling

`padding` sets the spacing of every padded region from the shared spacing scale, the same as [Pane](?path=/docs/components-pane--docs) and [Callout](?path=/docs/components-callout--docs):

```html
<craft-card label="Entry" padding="lg"></craft-card>
```

Leave it unset and each region keeps its own default — the header is tighter than the body — which is what a card in an index renders with.

For the rest, the card exposes eight CSS parts and four `--c-card-*` custom properties, both listed in full under [Properties](#properties).

<Canvas of={CardStories.CustomProperties} sourceState="shown" />

```css
craft-card {
  --c-card-radius: 0;
  --c-card-shadow: none;
}
```

The card draws its own chrome but leaves attributes on the host alone, so an `id`, `style` custom properties, and `data-*` metadata can all be set on it directly.

## Accessibility

A card is a container, not a control.
It has no implicit role and does not receive focus, so the content decides the semantics.

- **Give the card a heading if it is one.** The `label` renders as plain text, not a heading element. When a card is a section of a page, slot a real heading into `label` so it lands in the document outline.
- **Name the header actions.** An icon-only button in the `actions` slot needs an `aria-label`; the card's label does not name it.
- **Keep a decorative thumbnail decorative.** Artwork that only repeats the label takes `alt=""` or `aria-hidden`. If it carries meaning the text does not, give it a name of its own.
- **Don't rely on `active` alone.** It changes only fill and border colors. Pair a selection with a checkbox, text, or another cue, and expose the selected state on the control that sets it.
- **Expose `collapsed` on its toggle.** The card has no toggle of its own. The button that collapses it needs `aria-expanded`.
- **Say what a cover image shows in the content.** The image is decorative, with an empty `alt`, so the card's title or other content has to carry its meaning.
- **Pass the luminance whenever it's known.** Without it, a cover card falls back to heavy black behind white, which keeps the text legible but hides more of the image.
- **Don't add text colors to a cover card's content.** It's white or black for a reason; a color of its own can lose its contrast against the image.
- **Don't make the whole card a link.** For a card that leads somewhere, put the link on its heading so the link's name is the heading, not the card's whole content, and other controls in the card stay reachable.
