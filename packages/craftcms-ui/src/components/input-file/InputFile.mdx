# Input File

`<craft-input-file>` is a file field: a button that opens the file dialog, and a list of what has been chosen.

<Canvas of={InputFileStories.Default} sourceState="shown" />

It is built on Lion's file input rather than [Input](?path=/docs/form-controls-text-controls-input--docs), because it manages a list of files rather than a text value — so the base control's `maxlength`, `size`, `width`, and friends do not apply here.

## Choosing Files

`multiple` allows more than one file, and the list grows as they are added:

<Canvas of={InputFileStories.Multiple} sourceState="shown" />

`accept` limits what the dialog offers, using the same syntax as the native attribute:

<Canvas of={InputFileStories.WithAccept} sourceState="shown" />

`accept` filters the dialog; it is not a guarantee. A file can still arrive by other routes, so validate on the server too.

## Validation

Lion supplies file-type and file-size validators, and their messages render in the `feedback` slot alongside any of your own.

## Slots

The dialog button comes from the component, as a `craft-button` in the `file-select-button` slot.
Slotting your own replaces it — useful when the button needs different wording or a different variant, though the default already carries the label Lion computes.

## Accessibility

The button is a real button and the file list is real content, so both are reachable and announced without help.

The selection is the part worth attention: after choosing files, what changed is the list, not the button. If a page needs that announced, it should say so itself.

The label, help text, and error guidance under [Input's Accessibility section](?path=/docs/form-controls-text-controls-input--docs#accessibility) applies here too. On top of that:

- **Say what's accepted.** `accept` only filters the file dialog, and nothing on screen lists the allowed types or the size limit. Put both in the help text ("PNG or JPG, up to 5 MB"), so people know before they pick a file rather than after it is rejected.
- **Reword the button with `button-label`, not a replacement.** The component copies the field label onto its own button's `aria-labelledby` and wires its click to the dialog. A button slotted into `file-select-button` gets neither, so if you must replace it, give it visible text, include the field label in its accessible name, and open the dialog yourself.
- **Keep the button when you enable the drop zone.** `enable-drop-zone` adds a drag target around the button; it does not replace it. Dragging must never be the only way to add a file.
