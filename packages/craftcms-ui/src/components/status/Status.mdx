# Status

`<craft-status>` is a colored dot standing for an object's state.

<Canvas of={StatusStories.Default} sourceState="shown" />

It carries no text of its own and is meant to sit beside the thing it describes — an index row, a [Chip](?path=/docs/components-chip--docs), a page header — where the name is already present.

## States

`status` takes a fixed vocabulary, each with its own color:

Leaving it unset renders the neutral dot:

### Shapes

When the user turns on the "Use shapes to represent statuses" preference, which adds `use-shapes` to `<body>`, each state takes its own shape too, so states differ by more than color. There's nothing to set: `pending` is a triangle, `expired` a square, and the rest stay circles.

## Status, Indicator, or Badge?

Three components draw a small colored mark, and they are not interchangeable:

- **Status** — a fixed set of object states (`live`, `pending`, `expired`, `disabled`, `enabled`). Reach for it when the meaning is one of those.
- **[Indicator](?path=/docs/components-indicator--docs)** — any palette color, and appearance options. Reach for it when the dot means something the status vocabulary does not cover.
- **[Badge](?path=/docs/components-badge--docs)** — a dot _and_ a label in a pill. Reach for it when the state needs naming in place rather than in the row beside it.

## Accessibility

The dot is a colored shape, so on its own it conveys nothing to a screen reader. With a `status` set, it is exposed as `role="img"` with an accessible name, which is what makes the state perceivable.

Without a `label`, the name is "Status: live" derived from the state. Set `label` when that is not what a person needs to hear:

<Canvas of={StatusStories.CustomLabel} sourceState="shown" />

A status with neither `status` nor `label` has no name and is not exposed as an image at all.

**Show the state in visible text too.** Carry it in the surrounding row, so its meaning doesn't rest on the dot alone. When text beside the dot names the state, the dot is decorative: its color doesn't need to contrast with what's behind it.

**A dot without text beside it** is the only cue to the state. For someone who can't tell the colors apart and has turned on "Use shapes to represent statuses", its shape is all they have. So:

- Prefer a [Badge](?path=/docs/components-badge--docs) when there's room. It names the state in words.
- Only `pending` (a triangle) and `expired` (a square) have shapes of their own. `live`, `enabled` and `disabled` are all circles, so on their own they differ by color alone. Show those states in text.
- The dot must reach 3:1 against what's behind it, so the shape is visible. The status colors do on the default, white, sunken, page and details surfaces, on selected and hovered rows, and on tinted card headers, in both themes. In a selected card's header, the dot takes a ring in the header's text color instead. Anywhere else, check the contrast.
