# Status

`<craft-status>` is a colored dot standing for an object's state.

<Canvas of={StatusStories.Default} sourceState="shown" />

It carries no text of its own and is meant to sit beside the thing it describes — an index row, a [Chip](?path=/docs/components-chip--docs), a page header — where the name is already present.

## Status, Indicator, or Badge?

Three components draw a small colored mark, and they are not interchangeable:

- **Status** — a fixed set of object states (`live`, `pending`, `expired`, `disabled`, `enabled`). Reach for it when the meaning is one of those.
- **[Indicator](?path=/docs/components-indicator--docs)** — any palette color, and appearance options. Reach for it when the dot means something the status vocabulary does not cover.
- **[Badge](?path=/docs/components-badge--docs)** — a dot _and_ a label in a pill. Reach for it when the state needs naming in place rather than in the row beside it.

## Accessibility

The dot is a colored shape, so on its own it conveys nothing to a screen reader. With a `status` set, it is exposed as `role="img"` with an accessible name, which is what makes the state perceivable.

Without a `label`, the name is "Status: live" derived from the state. Only the "Status:" part is translated; the state itself is the raw key. Set `label` when that is not what a person needs to hear, including on non-English pages:

<Canvas of={StatusStories.CustomLabel} sourceState="shown" />

A status with neither `status` nor `label` has no name and is not exposed as an image at all. A dot with a `status` always has a name, though, even when adjacent text already spells the state out, so in that case a screen reader hears the state twice.

**Color is the only visual signal here.** Every state is the same circle, so in a dense list the whole meaning rests on hue. Carry the state in visible text in the surrounding row too, rather than relying on the dot alone.
