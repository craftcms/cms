# Select Rich

`<craft-select-rich>` is a dropdown whose options can hold arbitrary markup.

<Canvas of={SelectRichStories.Default} sourceState="shown" />

Options are [Option](?path=/docs/form-controls-select-controls-option--docs) elements rather than native `<option>`s, so each one can carry an icon, a status dot, a hint, or a thumbnail. The selected option is cloned into the invoker, so whatever an option looks like in the list is what the closed control shows.

## What It Costs

Replacing the native dropdown means replacing everything the platform gave you with it — the mobile picker, the built-in type-ahead, the keyboard model. Lion reimplements the keyboard and ARIA behavior, but a person on a phone gets a custom list where they expected the system one.

So use [Select](?path=/docs/form-controls-select-controls-select--docs) unless an option genuinely needs to be more than text. "It looks nicer" is not that reason.

## Sizing

The invoker sizes itself to its content rather than to a fixed width, so a control holding short values does not stretch across the row.

`small` renders it at the smaller size.

## Searching

`searchable` leads the open list with a search field, for a select with more options than you'd want to scroll. It filters the options by their label and hint, and by a `data-keywords` attribute for terms an option doesn't show. A badge or other slotted extra isn't matched.

<Canvas of={SelectRichStories.Searchable} />

Focus moves into the field when the list opens and stays there: the arrow keys move through the matches, Enter picks the highlighted one, and Escape clears the field, then closes the list. The field is a combobox controlling the listbox, so the highlighted option is announced as it moves.

## Accessibility

Lion supplies the listbox semantics, the wiring between label, invoker, and options, and the keyboard model. Opening the list moves focus to the listbox, which tracks the highlighted option with `aria-activedescendant`.

Give it a visible label that names what is being chosen. The invoker is announced with the label and the selected option together.

The thing to watch is what an option _announces_. Rich markup is read out too, so an option carrying an icon, a label, and a hint is announced as all three. Keep the visible label first and the decoration after it, and mark purely decorative artwork as such — otherwise every option in the list starts with the same noise. A `craft-icon` without a `label` is already hidden. Artwork that carries meaning needs a text alternative.

A status dot or colored icon can't be the only thing that tells options apart. Put the status in the option's text, as the `RichOptions` story does.
