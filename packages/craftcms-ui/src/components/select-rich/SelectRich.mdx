# Select Rich

`<craft-select-rich>` is a dropdown whose options can hold arbitrary markup.

<Canvas of={SelectRichStories.Default} sourceState="shown" />

Options are [Option](?path=/docs/form-controls-select-controls-option--docs) elements rather than native `<option>`s, so each one can carry an icon, a status dot, a hint, or a thumbnail. The selected option's content is copied into the field, so whatever an option looks like in the list is what the closed control shows.

## What It Costs

Replacing the native dropdown means replacing everything the platform gave you with it — the mobile picker, the built-in type-ahead, the keyboard model. The component reimplements the keyboard and ARIA behavior, but a person on a phone gets a custom list where they expected the system one.

So use [Select](?path=/docs/form-controls-select-controls-select--docs) unless an option genuinely needs to be more than text. "It looks nicer" is not that reason.

## Sizing

The field sizes itself to its content rather than to a fixed width, so a control holding short values does not stretch across the row.

`small` renders it at the smaller size.

## Accessibility

The field is a select-only combobox, as in the APG example: it keeps focus while the list is open and tracks the highlighted option with `aria-activedescendant`.

Give it a visible label that names what is being chosen. The field is named by the label, and shows the selected option.

The thing to watch is what an option _announces_. Rich markup is read out too, so an option carrying an icon, a label, and a hint is announced as all three. Keep the visible label first and the decoration after it, and mark purely decorative artwork as such — otherwise every option in the list starts with the same noise. A `craft-icon` without a `label` is already hidden. Artwork that carries meaning needs a text alternative.

A status dot or colored icon can't be the only thing that tells options apart. Put the status in the option's text, as the `RichOptions` story does.
