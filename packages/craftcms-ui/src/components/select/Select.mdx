# Select

`<craft-select>` is a dropdown built on the native `<select>`.

<Canvas of={SelectStories.Default} sourceState="shown" />

The options are real `<option>` elements, so the browser draws the dropdown itself.

## Why the Native Control

On a phone or tablet, the native picker is a full-screen wheel or list the person already knows how to use — better than anything a component can draw, and it comes with keyboard support, type-ahead, and screen reader behavior for free.

That is the trade this component makes: you get the platform's dropdown, and in exchange the options can only be text.

## Choosing Between the Three

- **Select** — plain text options. The default choice.
- **[Select Rich](?path=/docs/form-controls-select-controls-select-rich--docs)** — an option needs more than text: an icon, a status, a hint.
- **[Combobox](?path=/docs/form-controls-select-controls-combobox--docs)** — the list is long enough that a person needs to filter it.

Reach for the plainest one that fits. Each step up trades platform behavior for presentation.

## In PHP

In a Craft control panel screen, or a plugin's `settingsUi()`, describe the UI with `CraftCms\Cms\Ui\Ui` instead of writing markup.
`CraftCms\Cms\Ui\Controls\Choice` renders a select by default:

```php
use CraftCms\Cms\Ui\Controls\Choice;
use CraftCms\Cms\Ui\Nodes\Field;
use CraftCms\Cms\Ui\Ui;

Ui::make([
    Field::make('Site', Choice::make('siteId')
        ->options([
            ['label' => 'English', 'value' => 1],
            ['label' => 'Deutsch', 'value' => 2],
        ])
        ->placeholder('Choose a site')),
]);
```

`placeholder()` adds an empty first option.
An option can also have `disabled` and `group` keys. Options with the same `group` are listed together under it.
The same control renders as [radio buttons](?path=/docs/components-radio-group--docs), [checkboxes](?path=/docs/components-checkbox-group--docs), or a [button group](?path=/docs/components-button-group--docs) with `presentation()`.

## Accessibility

The native select brings its own semantics, keyboard handling, and mobile affordances, and Lion wires the label and validation feedback around it.

Label it with the thing being chosen. A select is announced with its current value, so an unlabeled one reads as a value with no question attached.

Group related options with `<optgroup label="…">` rather than indenting or prefixing option text, so the grouping is announced.

Don't submit the form or navigate when the value changes. Keyboard users step through the options with the arrow keys, and each step changes the value.
