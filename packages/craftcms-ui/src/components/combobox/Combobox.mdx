# Combobox

`<craft-combobox>` is a single-select dropdown with type-ahead filtering.

<Canvas of={ComboboxStories.Default} sourceState="shown" />

Reach for it when a list is long enough that scanning it is work — sections, fields, users, anything running to dozens of entries. For a short list, [Select](?path=/docs/form-controls-select-controls-select--docs) is less machinery and gets the native picker on touch devices.

## Options as Data

The combobox takes an `options` array and renders only the matching subset as [Option](?path=/docs/form-controls-select-controls-option--docs) children.

<Canvas of={ComboboxStories.LargeList} sourceState="shown" />

That is what makes a long list workable: the DOM holds the matches, not the source. `limit` caps how many are rendered at once, so a search matching hundreds of entries still produces a bounded list.

Keyboard navigation works over whatever subset is currently rendered.

## Clearing

`clearable` adds a control to empty the field:

<Canvas of={ComboboxStories.Clearable} sourceState="shown" />

Offer it whenever no selection is a valid answer. Without it, a person who picks something by accident has no way back to nothing.

`show-selected-hint` keeps the selected option's hint visible in the closed field, for when the hint is what distinguishes two similarly named entries.

## Events

Bind the native events, the same two a text input gives you:

```js
combobox.addEventListener('input', () => preview(combobox.value));
combobox.addEventListener('change', () => save(combobox.value));
```

`input` fires on every alteration, typed or selected. `change` fires when the value is committed — an option is chosen, or the field is left after typing. Both are dispatched from the component, so `event.target` is the combobox rather than the textbox inside it. Setting `value` from code fires neither, as on a native control.

`value` is a string, or an array of strings with `multiple-choice`.

## In PHP

In a Craft control panel screen, or a plugin's `settingsUi()`, describe the UI with `CraftCms\Cms\Ui\Ui` instead of writing markup.
`CraftCms\Cms\Ui\Controls\Combobox` renders a combobox, and `BooleanMenu` renders one with yes and no options:

```php
use CraftCms\Cms\Ui\Controls\BooleanMenu;
use CraftCms\Cms\Ui\Controls\Combobox;
use CraftCms\Cms\Ui\Nodes\Field;
use CraftCms\Cms\Ui\Ui;

Ui::make([
    Field::make('Provider', Combobox::make('provider')
        ->options([
            ['label' => 'anthropic', 'value' => 'anthropic'],
            ['label' => 'openai', 'value' => 'openai'],
        ])
        ->placeholder('Use default')
        ->showAllOnEmpty()
        ->clearable()),
    Field::make('Status', BooleanMenu::make('enabled')
        ->yesLabel('Enabled')
        ->noLabel('Disabled')
        ->includeEnvVars()),
]);
```

An option can have `data.hint` text, which is shown after its label.
An `optgroup` option, with its own `options`, groups the ones it holds.
`requireOptionMatch()` only accepts values from the list, `multiple()` accepts several, and `limit()` caps how many are listed.
`includeEnvVars()` also suggests environment variables.

## Accessibility

The combobox follows the ARIA 1.2 combobox pattern: the textbox is the combobox and keeps focus, pointing at the active option with `aria-activedescendant`. The requirements, and the gaps still open, are in `combobox.a11y.md`.

Give every combobox a visible label, through `label`, the `label` slot or `craft-field`. Don't rely on `placeholder`, which disappears as soon as someone types. If the label lives elsewhere, such as a table column heading, point a host `aria-labelledby` at it; an `aria-label` used instead must contain the text shown beside the field.

When `requireOptionMatch` is `false`, the field accepts values that aren't in the list. Say so in the label or help text, so people know they can type their own.

An option's `indicator` color only reinforces its label: "Online" and "Offline" carry the meaning, the green and red don't.

## Properties

The `options` array is a property rather than an attribute, so bind it with `.options`.
