# Pane

`<craft-pane>` is the control panel's primary content surface — a padded, rounded container with optional header and footer regions.

<Canvas of={PaneStories.Default} sourceState="shown" />

Panes wrap page sections, forms, tables, and modal bodies. It is the most-used component in the library, and the one that gives a page its structure.

For a block that represents a _thing_ rather than a section of a page — an entry, an asset, a user — use [Card](?path=/docs/components-card--docs).

## Scrolling

A pane that clamps its height scrolls its content — either through `variant="code"` or by setting `--c-pane-max-block-size`:

<Canvas of={PaneStories.ScrollableCode} sourceState="shown" />

**A scrolling region has to be reachable by keyboard.** Someone using a keyboard or a switch with no pointer otherwise cannot read past the clamp, which fails WCAG 2.1.1.

So when — and only when — the content actually overflows, the pane makes its own scroll container a labelled tab stop. It is conditional because a tab stop that cannot scroll anywhere is a focus trap with nothing to do.

Do not put `tabindex` on the host yourself. The host is not the scroller, and browsers only scroll the focused element or a scrollable _ancestor_ of it — never a descendant.

## Padding

`padding` takes the shared spacing scale, defaulting to `lg`:

<Canvas of={PaneStories.Padding} sourceState="shown" />

Values off that scale are ignored; set `--c-pane-padding` for anything else. This is the same `Paddable` behaviour [Callout](?path=/docs/components-callout--docs) uses.

## Styling

<Canvas of={PaneStories.CustomProperties} sourceState="shown" />

The pane exposes seven CSS parts — `base`, `header`, `title`, `header-actions`, `body`, `footer`, and `footer-actions` — and thirteen custom properties. Both are listed under [Properties](#properties).

`base` is the outermost element and the scroll container, so it is the one carrying the surface treatment and, when content overflows, the focus ring.

## Accessibility

The `label` renders as a heading in the header, which puts the pane in the document outline.

It renders at `heading-level`, which defaults to `2`. A CP page has its own `<h1>`, and pages routinely stack two or three panes, so a pane that claimed `<h1>` would flatten the heading list a screen reader navigates by.

Set `heading-level="1"` for a pane that really is the page's main heading, or a deeper level for a nested one:

```html
<craft-pane label="Settings" heading-level="3"></craft-pane>
```

Slotting your own heading into `title` still overrides all of this.
